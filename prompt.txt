Воссоздай проект Quote Catalog Service на Python + FastAPI.

Требования к проекту:

1. Создай FastAPI-приложение (файл main.py) с обработчиками:
   - GET /health
   - POST /catalog/source
   - POST /import
   - PUT /catalog/{quote_id}
   - DELETE /catalog/{quote_id}
   - GET /quotes/{quote_id}
   - GET /stats

2. Добавь веб-сервер (uvicorn). Настройки веб-сервера должны получаться из аргументов командной строки: --host (по умолчанию 0.0.0.0) и --port (по умолчанию 8000). main.py должен запускаться с помощью Docker (создай Dockerfile).

3. У цитаты есть атрибут "источник" (source). Источники бывают "CATALOG" и "LOCAL". "CATALOG" — цитаты из удалённого источника данных (приходят через POST /import). "LOCAL" — то, что было добавлено с помощью PUT /catalog/{quote_id}.

4. GET /health всегда возвращает HTTP 200 с телом {"status": "healthy"}.

5. POST /catalog/source принимает в теле JSON вида {"url": "http://catalog.internal:9000"}, сохраняет URL в глобальной переменной и отвечает HTTP 200 с телом {"source": "http://catalog.internal:9000"}.

6. POST /import принимает большой JSON (до 120 МБ), который нельзя целиком загружать в оперативную память. Формат тела:
   - первая строка всегда '{"quotes": ['
   - последняя строка всегда ']}'
   - между ними каждая строка — отдельный JSON-объект цитаты в формате {"id": "q-0000001", "author": "Марк Аврелий", "text": "…", "tags": ["стоицизм"], "year": 170, "lang": "ru"}
   - данные списка разделены символом ','.
   Нужно потоковое чтение тела без загрузки целиком в память.
   Данные сохраняются в таблицу в БД SQLite с перезаписью, когда "id" — первичный ключ. Импортированные цитаты получают источник "CATALOG". Если приходит цитата с id локальной записи ("LOCAL"), она замещается снимком — это вытеснение (eviction), его нужно учитывать в счётчике evictions. Если во входящем JSON не оказалось записи по id, которая есть в БД в таблице, то запись из таблицы нужно удалить.
   Формат ответа: HTTP 200 {"imported": 340000, "dropped": 120}.

7. Если в любом запросе с телом передан невалидный JSON — отвечать HTTP 400.

8. PUT /catalog/{quote_id} — добавляет или заменяет одну цитату через витрину. quote_id — id записи в таблице БД. Тело запроса: {"author": "Марк Аврелий", "text": "…"}. Ограничения: author — от 1 до 200 знаков; text — от 1 до 16384 знаков. Ответ: HTTP 200 {"id": "q-0000001", "author": "Марк Аврелий", "text": "…"}. Нарушение границ — HTTP 422. Такая запись актуальна по определению: читателю она отдаётся сразу после ответа, и перечитывать её из каталога не нужно. Добавленная цитата получает источник "LOCAL".

9. DELETE /catalog/{quote_id} — редакция снимает цитату с публикации через витрину. Запись не удаляется (не удалять из БД), а помечается как снятая с публикации (флаг published = 0). quote_id — id записи в таблице БД. Ответ при успехе: HTTP 200 {"deleted": true}. Если запись не найдена: HTTP 404 {"detail": "not found"}. Снятая цитата читателям не отдаётся, даже если в каталоге она ещё есть, — до следующего снимка.

10. GET /quotes/{quote_id} — чтение цитаты читателем. Ответ содержит запись целиком — все поля, которые были у неё в снимке или в ответе каталога. Сначала витрина ищет цитату у себя (только опубликованные); если не нашла — обращается в каталог по адресу, заданному через POST /catalog/source (URL + "/quote/{quote_id}"). Ответ: HTTP 200 {"id": "q-0000001", "author": "Марк Аврелий", "text": "…", "tags": ["стоицизм"], "year": 170, "lang": "ru"}. Ответ 200 обязан содержать заголовок X-Source: "LOCAL" — отдано из того, что витрина держит у себя; "CATALOG" — за этим ответом витрина обращалась в каталог. Если цитаты нет ни у витрины, ни в каталоге — HTTP 404 {"detail": "not found"}. Что цитаты нет, витрина не запоминает: редакция заводит их постоянно, и читатель, пришедший по свежей ссылке, обязан увидеть цитату сразу.

11. GET /stats — эксплуатационная сводка. Все величины — с момента старта процесса, только растут (кроме local, bytes и catalog). Ответ: HTTP 200 {"served_local": 10423, "served_from_catalog": 512, "catalog_reads": 96, "evictions": 148, "local": 63, "bytes": 516159, "catalog": 340000}.
    Поля:
    - served_local — сколько ответов читателям витрина отдала, не обращаясь в каталог
    - served_from_catalog — сколько ответов читателям потребовали обращения в каталог
    - catalog_reads — сколько запросов витрина отправила в каталог
    - evictions — сколько записей витрина удалила у себя, не считая ушедших из снимка
    - local — сколько записей витрина держит наготове сейчас (записи с source = "LOCAL")
    - bytes — сколько байт они занимают сейчас (байтовый размер локальных записей)
    - catalog — сколько цитат витрина знает сейчас (записи с source = "CATALOG")
    served_from_catalog и catalog_reads считаются независимо друг от друга и совпадать не обязаны.

12. Создай requirements.txt с зависимостями (fastapi, uvicorn[standard]).

13. Добавь автоматические тесты (pytest + fastapi.testclient):
    - conftest.py — фикстуры: временная SQLite-база (через tmp_path + monkeypatch подменяют main.DB_PATH), сброс глобальных счётчиков и catalog_source_url перед каждым тестом
    - tests/test_main.py — тесты всех эндпоинтов: /health, /catalog/source, /import (потоковый импорт, перезапись, удаление отсутствующих, evictions, невалидные тела), PUT /catalog/{quote_id} (валидация границ), DELETE /catalog/{quote_id} (снятие с публикации, 404), GET /quotes/{quote_id} (локальная выдача с X-Source: LOCAL, обращение в каталог с X-Source: CATALOG через мок urllib, 404, 502), GET /stats (пустые значения, счётчики)
    - requirements-dev.txt — зависимости для тестов: -r requirements.txt, pytest, httpx
    - Тесты должны использовать временную БД и не затрагивать рабочую quotes.db

14. Создай файл для Postman (postman_collection.json) — коллекция запросов для всех эндпоинтов (Health, Stats, Set catalog source, Add or replace quote, Unpublish quote, Import snapshot, Get quote) с переменной baseUrl = http://localhost:8000, примерами тел запросов и описаниями.

15. Добавь документацию OpenAPI: FastAPI генерирует схему автоматически. В main.py добавь Pydantic-модели (Quote, QuoteUpdateRequest, QuoteUpdateResponse, ImportResponse, StatsResponse, CatalogSourceRequest), теги, summary и description для эндпоинтов, описания ответов с примерами в параметре responses декораторов. Swagger UI доступен на /docs, ReDoc на /redoc, сырая схема на /openapi.json.

16. Веди README.md с описанием проекта, инструкциями по запуску, разделами о тестировании, Postman и OpenAPI, и документацией API.

17. Веди prompt.txt: поддерживай этот файл актуальным, чтобы он позволял воссоздать проект целиком. При каждом изменении проекта обновляй промпт так, чтобы он отражал все новые требования, поведение эндпоинтов, форматы запросов и ответов, структуру файлов и инструкции по запуску.

Формат входных данных импорта и формат ответов должны строго соответствовать описанному выше.
